# 自然噪声更新返回与帧内计数恢复

2026-10-27 在独立完整副本重新进行只读自然观察，补齐本轮的噪声更新返回采集。4次自然发现各产生一次动画事件、模型入队、延迟回调和监听，没有普通噪声发现→转身，也没有重复交付。此前多脚本记录的缺口保持原样，不补造缺失消息。

## 原生返回的独立核对

新探针由上一检查点的只读观察器派生，将噪声更新和状态切换各合并为一个入口监听器，没有运行第二个资格探针。除原函数的 onLeave 外，还在上层实际 `call` 后的 RVA `0x428bf3` 安装只读监听。

REA 在安装该指令监听之前解码到：`0x428bee: e8 0d c7 00 00` 调用 `0x435300`，下一条 `0x428bf3: 48 8b 4b 30` 为 `mov rcx,[rbx+0x30]`。共8条原始指令的字节与冻结原件和测试副本一致。载入证据 `ev_83da57d949b5aed2a8ef12e73ad904c92492780fdb7433a020510127861e1b71`；最终未截断状态 `ev_e97c9ce82d6a66d9351b00030267c3e4e2718c03f43727c66ccb555691ccd6e9`。

458个逐次记录均满足：同脚本、call序号、线程、对象、周期及调用方，严格按入口→值更新返回→噪声 onLeave→上层续行排列；onLeave与续行的字段读回相等。包括最初12个普通基线调用，以及4个发现周期内446个调用，未见缺失或多余返回。整个观察期间另有378432次入口、onLeave和续行的累计计数一致；累计数与458条逐次证明的范围分别保留，不能互相替代。

这证明当前单脚本方案可完整采集自然发现期间的返回；没有定位先前多脚本丢失 onLeave 的具体原因，也不推断先前游戏原函数未返回。

## 事件前的实际计数变化

按首次原生动画事件的原消息顺序截断，4周期分别有19、13、11、11条完整更新，共54条。每条均读到以下顺序：

`噪声入口 count=120 → 值管理器返回 count=119 → 噪声返回 count=120 → 上层续行 count=120`

警戒值在这54条入口/返回均为1，PlayerFound均为true，没有实际减值；阈值分别约0.430466、0.482272、0.607409、0.480287。因而这一轮不仅确认原生衰减计数确实递减，还把其随后净回升的范围收窄到**同一次原生噪声更新体内**。尚未逐条捕获具体写指令，不能把净变化直接命名为某条分支命中。

这与上一检查点“两个调用之间的净回升”不同：当前入口与返回均为120，跨调用净变化为0；如果只读取噪声入口和返回，会漏掉中间真实发生的120→119。值管理器的独立返回记录是区分这两者的依据。

4次发现均正常产生并交付事件，退出来自 `0x42c6e8` 的Found状态计时路径，没有走普通噪声 `0x435abf`。全观察另有42条声音读回，其中仅在第三周期找到1条首次事件前的样本，其余记录不能增加已发现周期的事件前覆盖。这个事件前样本及54条更新未满足PlayerFound=false、值低于阈值的共同前置，仍不支持自然噪声打断已经可达。

## 取消与漏发的判断边界

本轮没有发生事件前的发现→普通噪声转身，所以没有新增自然混合取消样本，也没有稳定来源跨事件点但缺少原生事件的候选。受控重放中已证明的正常混合退出与事件继续产生，见[原生噪声调用点报告](noise-callsite.md)，不能据此替代自然可达证据。

所有操作均来自用户正常输入；记录脚本不设置游戏对象、不主动调用噪声更新、不注入按键。Frida监听会增加执行开销，本轮时序不代表未插桩时的帧率。这里只报告本批条件，不能推广为所有帧率、暂停或重复发现组合都不可能打断。
